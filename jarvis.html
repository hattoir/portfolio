PROJECT / JARVIS

日常と研究開発を、
AIとつなぐ。

JARVISは、音声での情報取得や操作を入口に、知識・作業・AIエージェントをつなぐ統合AIシステムを目指す個人開発です。現在は、限られた操作と資料参照を確かめながら、少しずつ接続しています。

開発中 / 限定操作と資料参照を実装・検証

話しかけた先で、作業と知識につながる。

日常の操作を、短いやり取りで

音声で要求を伝え、許可されたPC操作や資料参照につなげることを目指しています。現在は集中モードの開始・終了と、固定資料の参照が中心です。

開発の続きを、AIと進める

調査をエージェントへ分担し、タスク・結果・判断を残す構想です。複数エージェントの模擬実行による経路確認と、実モデルによる調査完了は分けて検証しています。

自分の担当と、AIの担当。

自分が決めること

日常と開発をどう支援してほしいか、接続する範囲、操作の許可、結果を採用する条件。AIの出力を読み、次に試すことを判断します。

AIに分担すること

調査、実装案とコードの作成、テストの追加、ログの整理、差分のレビュー。AIが作成したコードを含む開発であり、本人がすべて手書きしたものではありません。

うまくいかなかったことから、設計を変える。

音声処理では、統合回復報告の合成入力5ターン中2ターンで誤認識がありました。HTTP応答や音声ファイルの生成だけで成功にせず、意図・状態・返答を別に確認しています。Phase 14では音声認識のヒントと意図判定を分けて比較しました。

応答の「検証済み」というラベルだけで操作完了にしないことも課題でした。実際の状態・版・セッションを読み戻して照合する修正を隔離環境で検証しています。

技術の役割と、これから。

OpenDots / MCP
エージェントとツールを接続する境界。専用経路を検証中で、汎用エージェントに無制限の操作権限を渡しません。
Ollama / ローカルLLM
ローカル推論基盤。実Researchの完了は未達で、模擬モデルの成功と区別しています。
音声認識・音声合成
操作の入口と返答。合成入力での処理を確認し、本人の実環境での受入を残しています。
Task Graph / Atlas / Vault
依存関係、実行状況、判断の根拠をつなぐ設計。全機能の本番統合を終えたわけではありません。

次は、本人の音声での受入、隔離候補の適用判断、条件を限定した実Researchの検証へ。ロボットやIoT、AR/MRとの接続は、その先の構想です。
